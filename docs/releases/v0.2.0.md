# NetScope v0.2.0 — Deep Diagnostics

NetScope v0.2.0 extends the Core Diagnostics release into a deeper network
troubleshooting tool. It adds permission-aware ICMP probes, explicit
connection strategy controls, report comparison, and portable CSV output
without changing the Technical Atlas interaction model.

## Highlights

- ICMP echo diagnostics with packet loss, RTT range, and per-packet samples.
- Hop-by-hop IPv4 and IPv6 traceroute with bounded hop counts.
- Runtime capability detection when raw ICMP sockets are unavailable.
- IPv4-only, IPv6-only, or automatic address preference.
- Custom TCP ports, GET/HEAD selection, and explicit redirect policy.
- Side-by-side timing and status comparison for two persisted runs.
- JSON and formula-safe CSV report downloads.
- Exact reruns with the original target, checks, and options.

## Run locally

Requirements:

- Docker with Compose support.
- Ports `5173` and `8080` available.
- A free PostgreSQL host port; set `POSTGRES_PORT` when `5432` is occupied.

```powershell
$env:POSTGRES_PORT = "5433"
docker compose --profile full up -d --build
```

Open <http://localhost:5173>. The supplied Linux container runs as the
unprivileged `netscope` user and grants `CAP_NET_RAW` only to the application
binary. Ping and traceroute availability is reported by
`GET /api/v1/capabilities`.

## Deep diagnostics

The diagnostic form keeps the common path compact and progressively reveals:

- connection strategy, probe timeout, and TCP ports;
- HTTP method, redirect following, and maximum redirect count;
- ICMP packet count and traceroute hop limit.

Run reports render ping as compact loss and RTT metrics and traceroute as a
numbered route journal. Raw structured data remains available under each
result.

## Comparison and exports

Open a report and choose **Compare run**, or visit:

```text
/runs/compare?left=<previous-run-id>&right=<current-run-id>
```

The comparison ledger shows per-check status, duration, and signed timing
change. Report actions provide both JSON and CSV downloads. CSV cells that
could be interpreted as spreadsheet formulas are escaped before export.

## Security model

All v0.1.0 SSRF controls remain active. `NETWORK_POLICY=public` rejects unsafe
resolved addresses, and the secure dialer pins connections to approved
addresses. ICMP destinations pass through the same resolution and address
policy before a packet is sent.

NetScope v0.2.0 still has no application authentication. Do not expose it
directly to the public internet without an external access-control layer.

## Known limitations

- Saved targets, schedules, status history, and notifications arrive in v0.3.0.
- Accounts, workspaces, and shared reports arrive in v0.4.0.
- Production deployment guidance, public authentication, and dark theme are
  part of the v1.0.0 hardening cycle.
