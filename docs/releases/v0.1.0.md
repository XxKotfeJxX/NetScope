# NetScope v0.1.0 — Core Diagnostics

NetScope v0.1.0 is the first complete diagnostic release. It accepts one
explicit hostname, URL, or IP address and runs bounded DNS, TCP, TLS, and HTTP
checks while streaming progress to the browser.

## Highlights

- Concurrent DNS, TCP, TLS, and HTTP probes.
- Live Server-Sent Events progress and cancellation.
- SSRF-resistant dialing with local and public network policies.
- PostgreSQL-backed run history and structured per-check results.
- JSON report export and repeatable diagnostics.
- Technical Atlas interface with a readable diagnostic route.
- Responsive dashboard, run report, history journal, and runtime reference.

## Run locally

Requirements:

- Docker with Compose support.
- Ports `5173` and `8080` available.
- A free PostgreSQL host port; set `POSTGRES_PORT` when `5432` is occupied.

```powershell
$env:POSTGRES_PORT = "5433"
docker compose --profile full up -d --build
```

Open <http://localhost:5173>. Health and readiness endpoints are available at
<http://localhost:8080/healthz> and <http://localhost:8080/readyz>.

Stop the stack with:

```powershell
docker compose --profile full down
```

The named PostgreSQL volume is preserved. Add `--volumes` only when the stored
run history should be deleted as well.

## API

The versioned API is rooted at `/api/v1`. The OpenAPI 3.1 contract is available
in [`api/openapi.yaml`](../../api/openapi.yaml).

Core endpoints cover:

- runtime capabilities;
- run creation, listing, details, and cancellation;
- Server-Sent Events progress;
- JSON report export;
- liveness and database-backed readiness.

## Security model

`NETWORK_POLICY=local` permits explicitly requested local and private targets
according to the configured allow flags. Public deployments must use
`NETWORK_POLICY=public`, which rejects loopback, private, link-local, multicast,
unspecified, and otherwise unsafe resolved addresses.

NetScope v0.1.0 does not include application authentication. Do not expose it
directly to the public internet without an external access-control layer.

## Known limitations

- ICMP ping and traceroute are planned for v0.2.0.
- Run comparison and CSV export are planned for v0.2.0.
- Saved targets, schedules, and notifications are planned for v0.3.0.
- Accounts, workspaces, and public report links arrive before v1.0.0.
